# Оркестратор прогонов НРИ и скоринг

Два скрипта под рубрику «За столом»: первый гоняет сессию пятью агентами и пишет
лог, второй превращает лог в таблицу баллов и отчёт о калибровке.

Материал сессии — `vypusk-1-wfrp-desyatina.md`. Промпты берутся оттуда на старте
прогона, копий в коде нет.

> **Неофициальное фанатское творчество.** Warhammer, Warhammer Fantasy Roleplay и
> связанные названия и символы — торговые марки Games Workshop Limited. Права на
> Warhammer Fantasy Roleplay четвёртой редакции принадлежат Cubicle 7 Games.
> Проект не связан с Games Workshop и Cubicle 7 и не представляет их.
>
> Правила системы, таблицы критических ранений, цифры оружия и брони здесь
> написаны с нуля под этот проект. Из книг не переносилось ничего.

## Установка

Нужен Python 3.10+. В системном Python на этой машине нет `pip`, поэтому всё
живёт в `.venv` внутри проекта:

```bash
.venv/bin/python -m pip install claude-agent-sdk
```

Если `.venv` надо пересобрать с нуля, а `pip` в системе так и нет:

```bash
python3 -m venv --without-pip .venv && python3 -c "import json,urllib.request,pathlib; d=json.load(urllib.request.urlopen('https://pypi.org/pypi/pip/json')); w=next(f for f in d['urls'] if f['filename'].endswith('py3-none-any.whl')); pathlib.Path('.venv/pip.whl').write_bytes(urllib.request.urlopen(w['url']).read())" && PYTHONPATH="$PWD/.venv/pip.whl" .venv/bin/python -m pip install claude-agent-sdk
```

## Авторизация

Прогон идёт **на подписке**, отдельный API-ключ не нужен: с середины 2026 план
Max включает кредит на Agent SDK. SDK тащит с собой бинарь Claude Code, а тот
берёт подписочные OAuth-креды из `~/.claude/.credentials.json`.

Два подводных камня, оба лечатся чистым окружением:

- `ANTHROPIC_API_KEY` перебивает подписку и молча жжёт платные кредиты;
- `ANTHROPIC_BASE_URL` уводит запросы на чужой эндпоинт.

`run.py` вычищает обе переменные сам, если не передать `--keep-env`. Для запуска
без браузера (cron, чужая машина) — `claude setup-token` и
`CLAUDE_CODE_OAUTH_TOKEN`.

## Этап первый: прогон

```bash
python3 orchestrator/run.py --provider stub --rounds 12   # сухой прогон, без токенов
python3 orchestrator/run.py --draw-vendors                # жребий: кому какой вендор
.venv/bin/python orchestrator/проверка.py --all           # что каждый API принимает
.venv/bin/python orchestrator/run.py --smoke openai       # дым-тест: пять кругов
.venv/bin/python orchestrator/run.py --round-zero-only    # живой круг ноль
.venv/bin/python orchestrator/run.py                      # полный прогон
```

Ключи: `--config`, `--out`, `--provider`, `--model`, `--rounds`, `--seed`,
`--round-zero-only`, `--draw-vendors`, `--smoke`, `--keep-env`,
`--continue-from`, `--final-from`, `--hard-final-from`.

Прогон кладёт в папку `runs/<метка времени>/`: `лог.jsonl` и снимок конфига.

### Что делает скрипт

- **Пять независимых контекстов.** Игрок видит только своё: ни промпта мастера,
  ни скрытой правды модуля, ни чужих целей и тайн. Агенты запускаются без
  инструментов и в пустой временной папке — дотянуться до файлов проекта нельзя.
- **Круг ноль.** Курт → Ансельм → Ханна → Лизель, строго по очереди, ход каждого
  немедленно уходит троим остальным. Мастер молчит и получает все четыре
  представления разом.
- **Режимы.** Мастер ставит `[РЕЖИМ: РАЗГОВОР]` или `[РЕЖИМ: ДЕЙСТВИЕ]` в конце
  сцены. В разговоре ходы последовательные и видны остальным, стартовый игрок
  сдвигается каждый круг. В действии — параллельно и вслепую. Тега нет — режим
  **РАЗГОВОР**: молчание толкуется в пользу диалога, потому что на диалоге всё
  и держится. Пропуск пишется в лог. Три круга ДЕЙСТВИЯ подряд — предупреждение
  `залипание_режима`.
- **Выбывшие.** Мастер объявляет `[ВЫБЫЛ: имя, причина]` — у выбывшего больше не
  спрашивают ходов и ему ничего не доставляют. Выбыл — это мёртв, без сознания
  или ушёл насовсем; если персонаж слышит и видит, он не выбыл. Возврат по
  `[ВЕРНУЛСЯ: имя]`, пробел в его истории остаётся: его там не было.
- **Счётчик круга.** В каждом сообщении мастеру — «Круг 18 из 30» и список
  выбывших. Без счётчика мастер не торопится: на прогоне без него сессия
  растянулась вдвое против ваншота.
- **Тайные ходы.** Ход, начатый словом `ТАЙНО`, уходит только мастеру. Ответ из
  блока `ТОЛЬКО ДЛЯ имя` — только этому игроку.
- **Броски кидает скрипт.** Мастер пишет `ПРОВЕРКА: имя, навык, сложность` и
  останавливается. Генератор с фиксированным зерном, зерно в логе, прогон
  воспроизводится. Если модель назвала число сама — случай помечается, мастеру
  уходит настоящий бросок.
- **Персонажи мира.** Мастер кидает и за Гретель, Йорга, Мунка, патруль и тварь —
  их характеристики лежат в `персонажи_мира` в конфиге. Для кого-то ещё мастер
  указывает целевое число прямо в строке: `ПРОВЕРКА: Хозяин мельницы (45),
  Обман, средне`. Это характеристика, а не бросок; кубик всё равно за скриптом.
- **Бой считает скрипт.** Мастер пишет `АТАКА: кто → по кому, чем` и
  останавливается. Скрипт проводит встречную проверку, переворачивает цифры
  броска для места попадания, вычитает броню и выносливость, списывает раны,
  бросает по своей таблице критов и присылает мастеру готовый результат словами.
  Раны считаются формулой из характеристик, а не задаются в конфиге.
- **Дубли.** 11, 22, … 99 и 100. Успешный дубль в атаке — критическое ранение при
  любом запасе ран, проваленный — фумбл. Скрипт решает, случилось ли; мастер
  описывает, как это выглядит.
- **Ноль ран — не смерть.** Дальше идут криты по локациям. Если критов в одну
  локацию больше бонуса Выносливости — конечность потеряна, для головы и корпуса
  это смерть. Смерть отменяется Судьбой, и **спрашивают об этом игрока**: ни
  скрипт, ни мастер за него не решают.
- **Состояния и травмы.** Кровотечение, оглушён, сбит с ног, ослеплён, сломлен —
  со штрафами к проверкам и напоминанием мастеру каждый круг. Травмы живут до
  конца сессии и запрещают естественное восстановление ран. Проверки
  кровотечения на нуле ран скрипт объявляет сам.
- **Стоп-условия.** Предел кругов, тег `[ФИНАЛ]`, все игроки выбыли, сбой агента. Лог пишется
  построчно с флашем: при любой остановке он уже целиком на диске.

### Листы, оружие и таблица критов

`config.json`: `персонажи`, `персонажи_мира`, `оружие`, `состояния`. Раны в
конфиге не хранятся — считаются по формуле размера (`СБ + 2·ТБ + СВБ` для
среднего) с учётом таланта Выносливый. Контрольная сверка для наших четверых —
12, 13, 15, 11; если не сходится, сломана реализация, а не цифры.

Таблица критических ранений — `orchestrator/криты.json`, шесть локаций по
возрастанию тяжести. Она написана с нуля под этот проект: копировать таблицы из
книги нельзя. Там же сроки и сложности лечения травм.

Цифры оружия и брони тоже наши. Качества заложены целиком — Ранящее,
Пробивающий, Рубящий, Колющий, — хотя в этом модуле встречается только
Пробивающий у молота Ансельма.

### Продолжить прерванный прогон

```bash
.venv/bin/python orchestrator/run.py --continue-from runs/X/лог.jsonl \
    --rounds 60 --final-from 45 --hard-final-from 54 --out runs/X-2
```

`--rounds` здесь — общий предел, а не сколько добавить: прогон продолжается с
круга, следующего за последним в старом логе.

Восстановление идёт **подачей истории из лога**, а не через `resume` у
провайдера. Дороже на одну большую подачу, зато работает с любой моделью — во
втором выпуске за столом будут stateless-адаптеры, и своей истории они не
помнят. Каждому агенту подаётся ровно то, что он видел: чужие тайные ходы,
чужие личные блоки и ходы из режима ДЕЙСТВИЕ в его историю не попадают.
Восстанавливаются и номер круга, и режим, и фаза ротации, и числа, которые
скрипт уже выдавал.

### Контекст не режется

История отправляется агентам целиком, окна и сводок нет. Урезав её, мы мерили бы
не игру модели, а качество своей сводки: память языковой модели — это и есть
переотправленная история. Провалы внимания на длинном контексте — результат
эксперимента, а не помеха, и они попадают в критерий «Ружья» у мастера.

Вместо урезания в лог пишется размер контекста и время ответа по каждому кругу,
а в отчёт — раздел «Разгон». На шестидесятикруговом прогоне это выглядело так:
контекст вырос в 4,8 раза, ответ замедлился с 39 до 97 секунд на круг.

### Финальный нажим

Мастер сам не торопится: тридцать кругов упёрлись в предел посреди сцены.
`--final-from N` начинает подмешивать мастеру давление таймера, `--hard-final-from N`
прямо требует развязки и тега `[ФИНАЛ]`. Оба ключа дублируются в конфиге
(`финал_с_круга`, `жёсткий_финал_с_круга`).

### Где менять провайдеров

`orchestrator/config.json`, ключи `мастер` и `игроки`:

```json
"игроки": {
  "Курт":   { "провайдер": "claude", "модель": "haiku" },
  "Лизель": { "провайдер": "openai", "модель": "gpt-…" }
}
```

Провайдер — это класс из `orchestrator/src/providers/` с двумя методами:
`открыть(агент, системный_промпт, модель)` и `отправить(текст) -> Ответ`.
Чтобы посадить за стол GPT, Gemini или Grok, нужен только новый файл рядом с
`claude.py` и строчка `зарегистрировать("openai", ПровайдерOpenAI)`. Оркестратор
про модели ничего не знает и трогать его не придётся.

Историю может держать сам провайдер (как Claude SDK) или адаптер, пересылающий
весь транскрипт заново — интерфейсу всё равно.

### Четыре вендора за столом

Мастер и судья идут по подписке Claude. Игроки — по одному на вендора:
Claude Sonnet, `gpt-5.6-terra`, `qwen/qwen3.7-max`, `grok-4.5`. GPT и Grok
подключены напрямую, Qwen — через OpenRouter: прослойка избавляет от регистрации
в китайском облаке и обходится дешевле прямого подключения.

`gemini-3.1-pro-preview` из состава этого выпуска выпал (не решился вопрос с
доступом), но [адаптер](orchestrator/src/providers/gemini.py) остаётся рабочим и
модель вернётся в следующих: строка лежит в конфиге в блоке `_вне_состава`.

`--draw-vendors` раздаёт вендоров персонажам жребием по зерну конфига. Раздача
руками дала бы повод сказать, что вендора подобрали под лист персонажа: у Лизель
Обаяние 52 и социальный набор, у Курта драка, а судья оценивает драму и
раскрытие тайны. Одно зерно — одна и та же раздача, проверяется повторным
запуском.

### Ключи

Только из окружения, ни в конфиге, ни в логе, ни в отчёте:

```bash
touch ~/.нри-ключи && chmod 600 ~/.нри-ключи
cat >> ~/.нри-ключи <<'КОНЕЦ'
export OPENAI_API_KEY="..."
export OPENROUTER_API_KEY="..."
export XAI_API_KEY="..."
КОНЕЦ
source ~/.нри-ключи
```

Claude ключа не просит — он на подписке, и `ANTHROPIC_API_KEY` из окружения
вычищается. `run.py` проверяет ключи только у занятых в прогоне вендоров и падает
до первого запроса: упасть на двадцатом круге из-за отсутствующего ключа — худший
из вариантов.

### Равные условия

Температура, лимит ответа, top_p и уровень размышления берутся из одного блока
`параметры_генерации` и раздаются всем игрокам без исключений. Всё выставленное
уходит в лог до первого хода и в отчёт отдельным разделом.

Выровнять удалось не всё, и это записано там же:

- температура, `top_p` и лимит ответа **не задаются** подписочным Agent SDK — у
  Claude идут вендорские умолчания. Поэтому общая температура и выбрана 1.0: это
  одновременно умолчание всех четверых и рекомендованный режим Gemini;
- размышление **нельзя выключить** у Gemini и Grok, нижняя ступень у обоих —
  «low». Выровнялись по ней; токены размышления считаются отдельной строкой;
- у OpenAI лимит ответа считает вместе с токенами размышления.

`проверка.py` выясняет живым запросом, что каждый API принимает на самом деле, а
что отвергает: документация про температуру у рассуждающих моделей молчит, а в
отчёт нельзя писать «вроде бы задаётся». Отвергнутый параметр снимается на ходу
и попадает в отчёт как расхождение, а не заминается.

### Прослойка под замком

OpenRouter — маршрутизатор: за одним именем модели может стоять несколько хостов
с разными сборками и разной квантизацией, и он вправе переключиться между ними
когда угодно. Молчаливое переключение посреди тридцатикругового прогона значило
бы, что вторую половину игры мы сравниваем не то, что думаем. Поэтому:

- `provider.order` из конфига (`апстримы_openrouter`) и `allow_fallbacks: false`
  — запасных хостов нет. Если единственный разрешённый лежит, запрос падает, и
  это правильно: упасть громко лучше, чем доиграть на другой сборке;
- `provider.require_parameters: true` — не отдавать запрос апстриму, который не
  умеет наши параметры генерации, иначе прослойка тихо выбросит температуру;
- кто ответил, пишется в каждый ход (`модель @ апстрим`), а смена посреди
  прогона — отдельным событием в логе и предупреждением в отчёте.

Актуальный список хостов у модели:

```bash
curl -s https://openrouter.ai/api/v1/models/qwen/qwen3.7-max/endpoints \
  | python3 -m json.tool
```

Кэш у Qwen через прослойку только явный: автоматического по префиксу нет
(`supports_implicit_caching: false`), в отличие от GPT и Grok. Пометки ставятся
на системный промпт, а если апстрим их не примет — снимаются, и нулевая доля
попаданий уходит в отчёт как разница в условиях, а не заминается. Деньги берутся
из `usage.cost` в ответе самой прослойки: это её счёт, он точнее пересчёта по
ставкам.

### Отказы

Модуль мрачный, и модель может отказаться играть сцену. Отказ распознаётся,
записывается отдельным событием с цитатой и **не повторяется**: тихий ретрай
спрятал бы ровно то, ради чего всё затевалось. Прогон при этом не падает —
персонаж считается промолчавшим, круг идёт дальше, текст отказа за стол не
уходит.

Ловля проверена с двух сторон: `проверка.py --отказ` шлёт заведомо отказный
запрос живому API, `tests/test_отказ_в_прогоне.py` гоняет прогон на подделке.
Без этого ноль в счётчике значил бы и «никто не отказался», и «мы не умеем
ловить».

### Дым-тест

`--smoke <вендор>` — пять кругов на одном вендоре, на выходе `реплики.txt`:
только реплики подряд, без тегов, бросков и служебных блоков. Задача одна —
прочитать глазами и убедиться, что модель не ломает русский. Урок Haiku
(«уходю», «троем остались», «замораживается на полу») стоил целого прогона, и
заметить такое можно только в сплошном тексте. Гонять для каждого нового
вендора **до** боевого запуска.

Автомат помечает в этом файле одно: буквы и знаки чужих алфавитов. У Qwen это не
праздная проверка — в русскую реплику проскакивает не столько `好`, сколько `。`
и `，`, похожие на обычные точку с запятой. Всё остальное — кальки, вывихнутые
падежи, мёртвые обороты — машина не видит, и файл сделан ровно для того, чтобы
его прочитали целиком.

## Этап второй: скоринг

```bash
# три слепых прохода судьи по всему логу
.venv/bin/python scoring/judge.py --log runs/X/лог.jsonl --out runs/X/судья.json

# продолженный прогон лежит в двух файлах — все скрипты берут несколько логов
.venv/bin/python scoring/judge.py --log runs/X/лог.jsonl runs/X-2/лог.jsonl \
    --out runs/X/судья.json

# выборка для ручной оценки: транскрипт, список кругов, пустая таблица
python3 scoring/human_export.py --log runs/X/лог.jsonl --rounds 15 --out runs/X/выборка

# судья по той же выборке, чтобы сравнивать сравнимое
.venv/bin/python scoring/judge.py --log runs/X/лог.jsonl \
    --rounds-file runs/X/выборка/круги.json --out runs/X/судья-выборка.json

# оценка мастера — та же машинка, другая рубрика
.venv/bin/python scoring/judge.py --log runs/X/лог.jsonl \
    --rubric scoring/rubric-gm.md --out runs/X/судья-мастер.json

# раскрытие ваншота — отдельный оценщик, он читает модуль
.venv/bin/python scoring/reveal.py --log runs/X/лог.jsonl --out runs/X/раскрытие.json

# сводный отчёт
python3 scoring/report.py --log runs/X/лог.jsonl --judge runs/X/судья.json \
    --judge-gm runs/X/судья-мастер.json --reveal runs/X/раскрытие.json \
    --human runs/X/выборка/оценка.csv --judge-sample runs/X/судья-выборка.json \
    --out runs/X/отчёт
```

**Раскрытие ваншота** считает не судья, а отдельный оценщик: пять вопросов по
модулю требуют знания скрытой правды, а судья модуля не читает — иначе он начнёт
мерить совпадение с разгадкой вместо игры. Оценщику правда даётся, и берёт он её
из промпта мастера в документе проекта, второй копии модуля нет. Вопросы лежат в
`scoring/раскрытие.json` — новый модуль означает новый файл, а не правку кода.

**Оценку мастера** ставит тот же слепой судья по `rubric-gm.md`: загадки, темп,
честность, рамка, ружья.

Судья слепой: в поданном ему транскрипте нет ни провайдеров, ни моделей, ни
стоимости, только имена персонажей и номера кругов. Модуль ему не показывают.
Три прохода идут в независимых сессиях, итог — медиана, разброс между проходами
попадает в таблицу.

Каждый балл требует цитаты. Скрипт сверяет цитату с логом: не найдена — балл в
медиану не идёт, и число отброшенных видно в отчёте.

Судья видит, кто когда выбыл и сколько кругов отыграл: иначе выбывший в середине
получил бы низкий балл за то, о чём его не спрашивали.

`--judge` необязателен: без него отчёт соберётся по логу — транскрипт,
счётчики, время и расход, а раздел баллов честно скажет, что судья не
запускался.

Отчёт кладёт `отчёт.md`, `баллы.csv`, `баллы.json`, `транскрипт.md` (для статьи,
с моделями) и `транскрипт-слепой.md`. В `отчёт.md` есть раздел «Калибровка» с
прямыми ответами да или нет на четыре вопроса из брифа и заготовка монтажного
листа из цитат.

## Тесты

```bash
python3 orchestrator/tests/test_dice.py      # кубики, сложности, автоматика, воспроизводимость
python3 orchestrator/tests/test_combat.py    # формула ран, урон, локации, криты, Судьба
python3 orchestrator/tests/test_parse.py     # теги режима, проверки, тайные ходы, самоброски
python3 orchestrator/tests/test_routing.py   # сухой прогон целиком и разбор лога
```

`test_routing.py` гоняет оркестратор на заглушках и сверяет по логу ротацию,
изоляцию тайного хода, адресность личных блоков и остановку по финалу.

## Формат лога

JSONL, одна строка на событие, поля русские. Типы событий: `старт`,
`продолжение`, `ход`, `доставка`, `бросок`, `аномалия`, `круг`, `финал`, `итог`.

У хода: `круг`, `режим`, `говорящий`, `порядок_в_круге`, `видимость`, `текст`,
`метки`, плюс `провайдер`, `модель`, `латентность_мс`, `токены`, `стоимость`.

Типы событий: `старт`, `продолжение`, `круг`, `ход`, `доставка`, `бросок`,
`атака`, `судьба`, `кровотечение`, `выбытие`, `возвращение`, `аномалия`,
`финал`, `остановка`, `итог`.

У атаки в логе: оба броска и целевые числа, разница уровней успеха, локация,
урон до брони, вычтенная защита, списанные раны, остаток, крит, назначенные
состояния и травмы.

Метки, за которые стоит хвататься на монтаже: `самоброс`, `тайный_ход`,
`личный_блок`, `тег_режима_пропущен`, `залипание_режима`, `непарсимая_проверка`,
`ошибка_агента`.

## Правки к промптам

`orchestrator/prompts/overrides/` — добавки, которых нет в документе проекта, но
без которых оркестратор не работает: теги режима и финала, формат проверок,
правила личных блоков, уточнение про тайный ход. Список с обоснованиями — в
`overrides/README.md`. После репетиции их надо слить обратно в документ.
